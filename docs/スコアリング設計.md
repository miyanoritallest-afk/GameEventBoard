## 1. 設計の更新点（旧 → 新）

DB設計書4.1 / design-decisions の前提を、実運用視点で以下のとおり更新する。

| 項目 | 旧設計 | 新方針（確定） | なぜ |
|---|---|---|---|
| ランク登録 | プロフィールで事前登録（user_season_ranks に永続） | **応募時に入力** | OWのランクは毎日変動しうる。常設プロフィール管理は実態に合わない |
| 次回初期値 | 履歴を再利用 | **使わない**（毎回入力が健全） | 同上。前回値を初期表示すると古いランクで応募する事故 |
| 入力シーズン数 | 履歴から直近 declared_seasons 抽出 | declared_seasons 分を**応募時に入力** | 何シーズン参照するかは主催者がイベントで決める（既存 `events.declared_seasons`） |
| role_swap=false | assigned_role の平均 | **担当ロール1つのスコアをそのまま使用**（個人ファイナルスコア不要） | 担当が1ロールなら平均不要。チームスコアは担当ロールスコアで算出 |
| role_swap=true | 全ロール平均 | 全ロール × declared_seasons の**2次元グリッド**を平均 | 交代シミュレーションに個人ファイナルスコアが必要なため全ロール参照 |
| 未認定ロール | （概念なし） | **新概念**。3方式を主催者が選択（後述2.3） | OWはロール毎に認定が必要で、苦手ロールは未認定の人がいる |
| 到達ボーナス | bonus_* カラム（0=実質オフ） | **イベントのオプションで有効化を明示選択** | 全イベントで使う項目でない。主催者が作成時にオン/オフ |
| 希望ロール | （スコアなし応募では省略） | **必須入力** | 3ロールある以上、全員が希望ロールに就けない。振り分けの基礎 |

## 2. スコア算出ロジック（新仕様）

### 2.1 入力データ（2次元グリッド）
応募時、主催者設定に応じて以下を入力する。

```
            シーズン①  シーズン②  …  シーズン[declared_seasons]
タンク        ランク     ランク         ランク
DPS          ランク     ランク         ランク
サポート      ランク     ランク         ランク
```

- 行（ロール）: role_swap_allowed=true なら3ロール全部、false なら担当（希望）ロール1つ。
- 列（シーズン）: events.declared_seasons の数。
- 各セルの値: rank_definitions のいずれか、または **未認定**。

### 2.2 role_swap による分岐
- **role_swap_allowed = false**: 担当ロール1つのスコア（declared_seasons 分の平均）を使う。個人ファイナルスコアは持たず、チームスコアは各メンバーの担当ロールスコアで算出。
- **role_swap_allowed = true**: 全ロール×全シーズンのグリッドを平均し individual_score（基礎）を算出。交代シミュレーションのため個人ファイナルスコアが必要。

### 2.3 未認定セルの補完（3方式・主催者がイベントで選択）
グリッド中の「未認定セル」を埋める方式。OSL実運用の定石。

| 方式 | 補完 | 例（タンク S③ が未認定） |
|---|---|---|
| **fill_by_role（横軸補完）** | 同一シーズンの他ロール平均で埋める | タンクS③ = S③のDPS・サポートの平均 |
| **fill_by_season（縦軸補完）** | 同一ロールの他シーズン平均で埋める | タンクS③ = タンクのS①・S②平均 |
| **exclude（除外）** | 未認定セルは平均計算に含めない | タンクS③は無視し、値のあるセルだけで平均 |

- どの方式を使うかは主催者がイベント作成時に選ぶ（初心者イベントは exclude が多い）。
- 補完不能なケース（例: 縦軸補完だが同ロールが全シーズン未認定）の取り扱いは実装時に定義（候補: そのロールを除外）。

### 2.4 ボーナス（オプション）
- イベントで「到達ボーナスを使う」を有効化したときのみ加算。
- final_score = base + bonus（peak 到達に応じた events.bonus_master/gm/champion）。
- peak（master/gm/champion/なし）も応募時に入力（常設しない方針と一貫）。

### 2.5 スナップショット
- individual_score / final_score を registrations に保存。
- score_breakdown(jsonb) に「参照したグリッド値・補完方式・補完後の値・ボーナス内訳」を記録（後から根拠を追える）。
- organizer_override_score があれば振り分け・平均でそれを優先（既存設計どおり）。

## 3. 実装の分割（依存順・4〜5 PR）

各PRで**テストも同時に**書く。PR-B が純粋ロジックでテストの主役。

| PR | 内容 | 主な成果物 | テスト |
|---|---|---|---|
| **PR-A** | rank_definitions マスタ seed ＋ 未認定の表現 | `supabase/seed.sql`（OW 40段階＋未認定の表し方） | seed 検証（件数・一意・sort_order） |
| **PR-B** | スコア算出 Service（純粋関数） | `src/lib/services/scoring.ts`（2次元グリッド・補完3方式・role_swap分岐・ボーナス） | 補完3方式×分岐×未認定の網羅単体テスト（主役） |
| **PR-C** | イベント設定の拡張 | マイグレーション（未認定補完方式カラム `uncertified_handling`・ボーナス有効化）＋作成/編集フォーム | スキーマ・フォーム |
| **PR-D** | スコアあり応募フォーム＋算出適用 | 希望ロール・ランクグリッド入力・未認定選択 → PR-B で算出 → registrations にスナップショット | 応募アクション結合（IDOR・なりすまし・算出値保存） |
| **PR-E**（任意） | 応募者一覧のスコア表示・運営上書き | registrations 表示拡張・organizer_override_score | 表示・上書き |

### 端ケースの確定仕様（2026-06-21 壁打ちで確定）
- **縦軸補完（fill_by_season）で同ロールが全シーズン未認定** → **そのロール行を除外**して残りで平均。
- **横軸補完（fill_by_role）で同シーズンが全ロール未認定** → **そのシーズン列を除外**して残りで平均。
- 上記の除外後、**有効な値が1つも無い**（＝全グリッド未認定） → **base = null（スコアなし）**。
- **role_swap=false で希望（担当）ロールが未認定** → **応募は可・score=null（スコアなし）**。運営が手動振り分けする余地を残す（初心者イベント・ロール人数調整に柔軟）。

### 確定（PR-C で実装済み）
- `events.uncertified_handling` enum: `fill_by_role` / `fill_by_season` / `exclude`（既定 exclude）。0007 で追加。
- スコア計算の有効化は既存 `events.require_score`（個人スコアを計算するか）で表現。OFF ならスコアなしイベント。
- ボーナス有効化は専用カラムを追加せず bonus_* の値で表現（フォームのトグルは UI 上の出し分けのみ）。

### ランク収集 × スコア算出は本来2軸（パターン②は別PR）
壁打ちで「ランク収集」と「スコア算出」が独立した2軸と判明（オーナーの3パターン）:
- ① 収集する＋算出する … 今の require_score=true（PR-A〜E で実装済み）。
- ② 収集する＋算出しない … 実力均等化のためランクだけ見る初心者向けイベント。**現状は表現手段なし**。
- ③ 収集しない＋算出しない … ランクフリーの突発イベント＝今の require_score=false。
- **②の実装は別PR**: `collect_rank` 的なフラグ追加＋応募フォームでランク入力（スコア算出なし）＋応募者一覧でランク表示。着手時に設計を壁打ちする。

## 4. 既存スキーマとの対応（DB設計書3章）

- `rank_definitions`（マスタ）: ランク↔スコア。PR-A で seed。未認定の表現方法は PR-A で確定。
- `events.declared_seasons` / `role_swap_allowed`: 既存。入力グリッドの形を決める。
- `events.bonus_master/gm/champion`: 既存。ボーナス。有効化オプションは PR-C で UI 化。
- `events` に未認定補完方式カラムを **追加**（PR-C・マイグレーション）。
- `registrations.individual_score / final_score / score_breakdown / organizer_override_score`: 既存。PR-D でスナップショット保存。
- `user_season_ranks` / `user_peak_achievement`: **当面使わない**（応募時入力・非永続方針のため）。将来「履歴を残したい」要望が出たら再検討。
