## B. 本番 Supabase プロジェクト（要作業）

開発用とは**別の本番プロジェクト**を用意する。

- [ ] Supabase で本番プロジェクトを作成。
- [ ] SQL Editor で `supabase/migrations/` の `.sql` を **`0001` から番号順にすべて実行**（37本・順序依存）。スキーマ・RLS・security definer 関数・Realtime publication まで含む。
- [ ] 必要ならマスタの seed（`rank_definitions` 等）を投入。
- [ ] **Authentication > Providers で Discord を有効化**。本番用の Discord OAuth クライアントID / シークレットを設定。
- [ ] Discord アプリのリダイレクト URL に `<本番APP_URL>/auth/callback` を登録。
- [ ] （通知の Bot DM を使うなら）Discord Bot を対象サーバーに招待。

## C. Vercel（要作業）

- [ ] リポジトリを Vercel に接続。
- [ ] 環境変数を設定：
  - 必須：`NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY`
  - 任意（機能有効化時）：`NEXT_PUBLIC_APP_URL`（**本番では必須級**。未設定だと通知内リンクが `localhost` になる）/ `DISCORD_BOT_TOKEN` / `CRON_SECRET`
- [ ] **Cron のプラン要件を確認**：`vercel.json` は 10分間隔（`*/10 * * * *`）。Vercel Hobby プランの Cron は 1日1回までの制限があるため、10分間隔で回すには **Pro プラン**が必要。Hobby で運用するならスケジュールを日次に変えるか、Cron を外部（GitHub Actions 等）に寄せる。
- [ ] デプロイ後、本番 URL で Discord ログイン → イベント作成 → 応募 → 観戦ビューの Realtime 更新までを 1 度通しで確認。
