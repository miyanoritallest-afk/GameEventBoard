# デプロイ手順（本番公開）

Vercel（ホスティング）＋ 本番 Supabase（DB/認証）へ公開する手順。初回向けに詳しく書く。
全体像は「① 本番 Supabase 構築 → ② Vercel 接続 → ③ 環境変数・OAuth 突き合わせ → ④ デモデータ投入」。

> **CD（自動デプロイ）について**：②で Vercel に GitHub リポジトリを接続した瞬間から自動で有効になる。
> 以降は `main` に push/merge するたびに Vercel が自動でビルド&デプロイする。別途 CD 設定は不要。

---

## ① 本番 Supabase プロジェクトの構築

開発用とは**別の本番専用プロジェクト**を作る。

### 1-1. プロジェクト作成
1. https://supabase.com にログイン →「New project」。
2. 名前（例 `matchpoint-prod`）・リージョン（例 Tokyo `ap-northeast-1`）・DBパスワードを設定して作成。
3. しばらく待つとプロビジョニング完了。

### 1-2. マイグレーション適用（37本を順番に）
1. 左メニュー「SQL Editor」を開く。
2. `supabase/migrations/` の `.sql` を **`0001` から番号順にすべて**貼り付けて実行する（37本・依存順なので順序厳守）。
   - スキーマ・RLS ポリシー・security definer 関数・Realtime publication まで含む。
   - 1本ずつ実行してエラーが出ないか確認していくのが安全。

### 1-3. マスタ seed（ゲーム・ランク定義）
- `supabase/seed.sql` を SQL Editor で実行（`OVERWATCH` のゲームマスタ・rank_definitions が入る）。

### 1-4. API キーを控える
- 「Project Settings > API」から次を控える（②で使う）:
  - **Project URL**（`https://xxxx.supabase.co`）
  - **anon public** キー
  - **service_role** キー（秘密。絶対にクライアントに出さない）

## ② Vercel へのデプロイ

### 2-1. アカウント作成・リポジトリ接続
1. https://vercel.com に **GitHub アカウントでログイン**（連携が楽）。
2. 「Add New… > Project」→ GitHub の `GameEventBoard` リポジトリを「Import」。
3. Framework Preset は **Next.js** が自動検出される。Build/Output はデフォルトのままでよい。
4. **まだ Deploy を押さない**（先に環境変数を入れる）。

### 2-2. 環境変数を設定（③で詳述）
Import 画面の「Environment Variables」に、下の③の変数を入れてから **Deploy**。
（後から「Project Settings > Environment Variables」でも追加・変更できる。変更後は「Redeploy」が必要。）

### 2-3. デプロイ完了
- ビルドが通ると `https://<プロジェクト名>.vercel.app` が発行される。これが本番 URL。
- **以降このリポジトリの `main` に push/merge すると自動で再デプロイ**される（＝CD）。

## ③ 環境変数・Discord OAuth の突き合わせ

### 3-1. Vercel に入れる環境変数
| 変数 | 値 | 必須 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 1-4 の Project URL | ✅ |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 1-4 の anon キー | ✅ |
| `SUPABASE_SERVICE_ROLE_KEY` | 1-4 の service_role キー | ✅ |
| `NEXT_PUBLIC_APP_URL` | 本番 URL（例 `https://matchpoint.vercel.app`・末尾スラッシュなし） | ✅（通知リンクが壊れる） |
| `DISCORD_BOT_TOKEN` | Bot DM を使うなら | 任意 |
| `CRON_SECRET` | 定期通知を使うなら（十分長いランダム文字列） | 任意 |

> `NEXT_PUBLIC_APP_URL` は初回デプロイ後に URL が確定するので、**デプロイ→URL確認→この変数を設定→Redeploy** の順でよい。

### 3-2. Discord OAuth（本番用）
1. https://discord.com/developers/applications で本番用アプリを作成（開発用と分けると安全）。
2. OAuth2 の「Redirects」に次を**両方**登録:
   - `https://<Supabaseプロジェクト>.supabase.co/auth/v1/callback`（Supabase の Discord Provider が使う）
   - （参考）アプリ側のコールバックは `https://<本番URL>/auth/callback`
3. Client ID / Client Secret を控える。
4. Supabase ダッシュボード「Authentication > Providers > Discord」を有効化し、上の Client ID / Secret を設定。
5. Supabase「Authentication > URL Configuration」の **Site URL** を本番 URL（`https://<本番URL>`）にする。Redirect URLs にも本番 URL を許可に追加。

### 3-3. Vercel Cron のプラン注意
- `vercel.json` は 10分間隔（`*/10 * * * *`）。**Vercel Hobby（無料）プランの Cron は 1日1回まで**の制限がある。
  - 10分間隔で回すには **Pro プラン**が必要。
  - Hobby のままなら `vercel.json` の schedule を日次（例 `0 0 * * *`）に変えるか、Cron を使わない運用にする。
  - 通知（試合リマインド等）が主目的なので、ポートフォリオ用途なら日次でも・無しでも支障はない。

## ④ デモ大会データの投入（採用担当向けの見せ球）

観戦ビューから「完成した大会（予選→順位→決勝トーナメント→表彰台）」を触れるようにする。

### 前提: 主催者アカウントを本番に作る
デモ大会の主催者はあなた（Discord 名「のり」）。**まず本番 URL で一度 Discord ログイン**して、
本番の `auth.users` / `public.users` に自分の行を作る。

### 投入
1. ログイン後、Supabase「SQL Editor」で `select id, discord_name from public.users;` を実行し、
   **自分（のり）の user_id** を確認する。
2. `supabase/prod_seed_demo_event.sql` を開き、先頭付近の
   `v_org_id uuid := '...';` を**その user_id に書き換える**（既定は開発時の id なので本番では別）。
3. 書き換えた SQL 全体を SQL Editor で実行する（冪等：再実行しても重複しない）。
4. `https://<本番URL>/events/event-mpvbcd/watch` を開くと、完成した大会の観戦ビューが見える。

> このデモは 70 名・12 チーム・予選30試合・決勝トーナメントまで結果入力済み。
> 採用担当が触ったときに「参加チーム／ブロック／順位／試合結果／トーナメント／表彰台」が全部埋まっている。
